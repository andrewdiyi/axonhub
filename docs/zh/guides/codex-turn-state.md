# Codex Turn-State（292/332）指南

本文介绍 AxonHub 内置的 `X-Codex-Turn-State` 采集与注入能力：它让官方 Codex 渠道用上可复用的 292/332 模板，减少被上游判定为降级（312/356）的机会。

> 该机制来自社区对官方 Codex 后端的观测，不是 OpenAI 公布的协议。长度本身不能证明模型质量，实际效果仍取决于上游。

## 它是什么

官方 Codex 后端在响应头里返回 `X-Codex-Turn-State`。这个值是 Fernet 令牌：

- 前 1 字节固定为 `0x80`，随后 8 字节是大端 Unix 时间戳（签发时间），其余是加密载荷
- 有效期由签发时间决定，共 1 小时
- 解码后长度有两种形态：个人版 217 字节（Base64 后 292 字符），Team 版 249 字节（332 字符）
- 被限流的路径会多出一个 AES 块：233 字节（312 字符）/ 267 字节（356 字符）

使用规则（由上游强制）：

1. 同一个值不能跨账号使用
2. 同一个值不能跨模型使用，即使账号相同
3. 同一个账号 + 同一个模型可以跨出口 IP 复用
4. 值只在签发后 1 小时内有效

AxonHub 按 **账号（从访问令牌解析出的 ChatGPT Account ID）+ 模型** 分桶存储模板，绝不跨桶使用。

## 工作方式

```
主动采集（TurnStateProbe）
  渠道加载 → 每 60 秒检查一次分桶
            → 缺少模板或剩余有效期不足 5 分钟
            → 用该渠道的凭据直连官方后端发一条最小请求
            → 读取响应头里的新模板并入库

被动采集（响应头钩子）
  业务请求 → 上游响应头带模板 → 入库

注入
  业务请求 → 命中官方 Codex 渠道
          → 按账号 + 模型查到可用模板
          → 写入 X-Codex-Turn-State 后发往上游
```

主动采集每次只处理一个分桶，因此一个渠道的请求速率约为「每个模型每小时一次」。请求体是最小的 `ping`，只读取响应头，随即关闭响应体。

## 适用范围与边界

- **仅官方 Codex 渠道**（`chatgpt.com` 基础地址）。中转站判定为 relay，既不采集也不注入，避免把官方凭据或状态发到第三方。
- **compact、image 等非对话请求**不注入。
- 上游返回 401 / 403 / 429 时，探测会退避 10 分钟，不会反复冲击账号。
- 模板保存在进程内存中。重启后由主动采集在下一个周期补齐（每个模型约 1 分钟）。
- 客户端自带的 `X-Codex-Turn-State` 不会被沿用：来源不明的值可能是其他会话的状态，AxonHub 只注入自己为该账号 + 模型采集到的模板。

## 配置

无需配置即可启用：渠道加载后自动开始采集，收到业务的官方 Codex 请求时自动注入。

紧急关闭（无需重新编译）：

```bash
AXONHUB_CODEX_TURN_STATE=off
```

取值为 `off`、`0`、`false`、`no` 时同时关闭采集与注入，其它情况保持启用。

可调参数在代码中定义：

| 参数 | 位置 | 默认值 |
| --- | --- | --- |
| 探测间隔 | `turnstate_probe.go` `defaultTurnStateProbeInterval` | 60 秒 |
| 续期阈值 | `turnstate_probe.go` `turnStateProbeRefreshMargin` | 5 分钟 |
| 拒绝退避 | `turnstate_probe.go` `turnStateProbePauseOnRefusal` | 10 分钟 |
| 令牌有效期 | `turnstate.go` `DefaultTTL` | 1 小时 |

## 传输协议说明

模板通过 HTTP 响应头传递，因此该能力在 **HTTP/SSE 上游传输**下最完整：每次请求都能带上新模板。

WebSocket 传输下，握手响应头只会被读取一次，注入也只在建立连接时生效；长连接内的多个回合无法逐轮刷新模板。如果渠道配置为 WebSocket 且希望完整使用该能力，把渠道端点的传输方式改为 `http`。
